🌊 ROiCORE คืออะไร?

“ระบบรับรายงานน้ำท่วม ประเมินความเสี่ยง และแสดงผลบนแผนที่”

1. รับรายงานด่วน

ประชาชนรายงานเหตุน้ำท่วมได้ภายใน ≤ 3 Taps พร้อมระบบระบุพิกัด GPS อัตโนมัติและแนบภาพถ่าย

2. ประเมินความเสี่ยง

คำนวณคะแนนความเสี่ยงอัตโนมัติ (น้ำขัง × พยากรณ์ฝน × ความถี่รายงาน) พร้อมวาดอาณาเขต Polygon เตือนภัย

3. แสดงผลบนแผนที่

แผนที่ OpenStreetMap แบบเรียลไทม์ ผสานภาพถ่ายดาวเทียม GISTDA 77 จังหวัด และแดชบอร์ดสรุปสถิติ

💬 พูดแค่นี้: “ROiCORE คือระบบรับรายงานสถานการณ์น้ำท่วม นำมาประเมินความเสี่ยงอัตโนมัติ และแสดงผลบนแผนที่แบบเรียลไทม์เพื่อช่วยเหลือประชาชนครับ”

🧩 Object ในระบบมีอะไรบ้าง?

การจำลองโลกความจริงของภัยพิบัติให้อยู่ในรูปแบบเชิงวัตถุ (Core Domain Entities & Value Objects)

FloodPoint
Entity

จุดเฝ้าระวังน้ำท่วมบนแผนที่ ประกอบด้วย พิกัด, รัศมีผลกระทบ, ระดับน้ำ (เมตร) และจำนวนรายงาน

FloodReport
Entity

รายงานจากประชาชน ประกอบด้วย ระดับความรุนแรง (1-4), เบอร์โทรศัพท์, รูปถ่ายสถานที่ และเวลาที่เกิดเหตุ

GeoLocation
Value Object

วัตถุพิกัดภูมิศาสตร์ (Lat / Lng) ควบคุมความถูกต้องของพิกัดในประเทศไทย (Lat -90 ถึง 90, Lng -180 ถึง 180)

RiskLevel
Enum

ระดับความเสี่ยง 4 ระดับ: CRITICAL (วิกฤต), HIGH (สูง), MEDIUM (ปานกลาง), LOW (เฝ้าระวัง)

💬 พูดแค่นี้: “ในระบบเราแบ่ง Object หลักออกเป็น 4 ตัวคือ FloodPoint จุดน้ำท่วม, FloodReport รายงานประชาชน, GeoLocation ดูแลพิกัด และ RiskLevel กำหนดระดับความเสี่ยงครับ”

🔄 3 Design Patterns หัวใจสำคัญ

แก้ปัญหาความซับซ้อนของระบบด้วย GoF Patterns ที่ตรงจุดและมีประสิทธิภาพ

Strategy Pattern

“คำนวณความเสี่ยง”

CompositeRiskStrategy: คำนวณความเสี่ยงอัตโนมัติจาก (ระดับน้ำท่วม × พยากรณ์ฝน 3 ชม. × ความหนาแน่นของรายงาน) สามารถสลับสูตรได้อิสระ

Repository Pattern

“จัดการข้อมูล”

SupabaseFloodReportRepository: ห่อหุ้มการ Query ฐานข้อมูล แยกคำสั่ง SQL/PostGIS ออกจากโค้ดระบบ ทำให้สามารถสลับไปใช้ Mock ในการทดสอบได้ทันที

Adapter Pattern

“เชื่อมต่อ API ภายนอก”

GistdaDisasterService & OpenWeatherService: แปลงโครงสร้างข้อมูลดาวเทียม GISTDA และสภาพอากาศภายนอกให้อยู่ในมาตรฐานเดียวกันของระบบ

💬 พูดแค่นี้: “เราใช้ 3 Pattern หลัก: Strategy ใช้คำนวณความเสี่ยง, Repository ใช้จัดการฐานข้อมูล, และ Adapter ใช้แปลงข้อมูลจาก API ภายนอกอย่าง GISTDA ครับ”

▶️ ระบบทำงานยังไง? (4 ขั้นตอน)

การเดินทางของข้อมูลตั้งแต่ประชาชนกดรายงาน จนถึงการวาดอาณาเขตบนแผนที่สด

01
รายงาน (Report)

ประชาชนเลือก 1 ใน 4 ระดับน้ำ ผ่านฟอร์มด่วน 3 Taps ระบบดึงพิกัด GPS อัตโนมัติ

02
ประเมิน (Evaluate)

Strategy วิเคราะห์ระดับความรุนแรง และตรวจจับ Cluster หากมีการรายงานซ้ำซ้อน

03
บันทึก (Persist)

Repository บันทึกลง Supabase Postgres + PostGIS และแคชข้อมูลเพื่อความเร็ว

04
แสดงผล (Render)

หมุดโผล่บน OpenStreetMap ทันที พร้อมวาดอาณาเขต Polygon สีแดงเตือนภัย

💬 พูดแค่นี้: “วงจรการทำงานง่ายมากครับ: 1. รายงานเหตุ ➔ 2. ระบบประเมินความเสี่ยง ➔ 3. บันทึกข้อมูล ➔ และ 4. แสดงหมุดพร้อมวาด Polygon บนแผนที่ทันทีครับ”
