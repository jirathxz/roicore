🌊 ROiCORE — Flood Intelligence Platform

“ระบบรับรายงานน้ำท่วม ประเมินความเสี่ยงอัตโนมัติ และแสดงผลบนแผนที่สด”

ปัญหาที่พบ (Pain Point)

ข้อมูลน้ำท่วมกระจัดกระจาย ล่าช้า และประชาชนรายงานเหตุฉุกเฉินได้ยากลำบาก

จุดประสงค์ของระบบ (Purpose)

รวมศูนย์รายงานภาคประชาชน ผสานภาพถ่ายดาวเทียม และแจ้งเตือนภัยแบบเรียลไทม์

1. รายงานด่วน ≤ 3 Taps

เลือกระดับน้ำ ➔ ใส่เบอร์ ➔ ส่งพิกัด GPS ทันที ไม่ต้องพิมพ์ยาว

2. ดาวเทียม GISTDA 77 จว.

ดึงชั้นข้อมูลน้ำท่วมจากดาวเทียมครอบคลุมทุกจังหวัดทั่วไทย

3. อาณาเขตน้ำท่วม Polygon

คำนวณและวาดขอบเขตพื้นที่วิกฤตบนแผนที่สดอัตโนมัติ

สูตรจำข้อ 1 (WHAT): "ROiCORE คือระบบรับรายงานน้ำท่วมด่วน ประเมินความเสี่ยง และแสดงผลบนแผนที่ดาวเทียมเรียลไทม์ครับ"

ระบบทำงานอย่างไร? (System Flow)

เส้นทางการเดินทางของข้อมูลแบบ End-to-End: ผู้ใช้ ➔ ฟังก์ชัน ➔ ประมวลผล ➔ แสดงผล

1. User ผู้ประสบภัย / ผู้สัญจร
2. เลือก Function รายงาน / ตรวจสอบจุด
3. Object ทำงาน Report + Risk Strategy
4. DB & Processing Supabase PostGIS
5. แสดงผลบน Map หมุด & อาณาเขตสด
ฝั่งผู้ประสบภัย (Flood Victim)

กดปุ่มแจ้งเหตุ ➔ เลือก 1 ใน 4 ระดับน้ำ ➔ ใส่เบอร์โทร ➔ ระบบดึง GPS อัตโนมัติและส่งข้อมูลขึ้นระบบทันที

ฝั่งผู้เดินทาง (Traveler)

เปิดแผนที่ OpenStreetMap ➔ ตรวจสอบจุดน้ำท่วมและสภาพอากาศ ➔ กรองข้อมูลรายจังหวัดบนแดชบอร์ดโดยไม่ต้องล็อกอิน

3. DESIGN — OOP & OOAD (แกนหลักสำคัญ)
WHAT ➔ HOW ➔ DESIGN ➔ RESULT
ROiCORE

การออกแบบด้วยหลักการเชิงวัตถุ (OOP & OOAD)

ซ้าย: Class Diagram แสดงความสัมพันธ์ | ขวา: 4 เสาหลัก OOP กับตัวอย่างจริงในระบบ

Simplified Class Diagram
<<abstract>> User ──┬──► FloodVictim (ส่งรายงาน) └──► Traveler (ตรวจเส้นทาง) FloodReport ──(สร้าง)──► FloodPoint ├── location: GeoLocation └── riskLevel: RiskLevel FloodPoint ──(ประเมิน)──► <<interface>> IRiskStrategy ↳ CompositeRiskStrategy <<interface>> IFloodRepository ◄── SupabaseFloodPointRepo
* แยก Domain Model เป็นอิสระจาก Database ตาม Clean Architecture
1. Encapsulation (ซ่อนข้อมูลภายใน) คลาส GeoLocation ซ่อนพิกัดเป็น private ตรวจสอบค่าพิกัดให้ถูกต้องเสมอ ป้องกันการป้อนพิกัดนอกโลก
2. Inheritance (การสืบทอดคุณสมบัติ) FloodVictim และ Traveler สืบทอดจาก User เพื่อใช้ตัวตนเดียวกันแต่มีพฤติกรรมแยกต่างหาก
3. Polymorphism (พหุสัณฐาน) IRiskStrategy เรียกเมธอด calculate() เหมือนกัน แต่คำนวณสูตรต่างกันตามกลยุทธ์ (ฝนตก/ระดับน้ำ)
4. Abstraction (การซ่อนความซับซ้อน) IFloodRepository ซ่อนคำสั่ง SQL และเชื่อมต่อ PostGIS ไว้เบื้องหลัง Domain สั่งบันทึกได้โดยไม่ต้องรู้ไส้ใน
สูตรจำข้อ 3 (DESIGN): "เราใช้ 4 เสาหลัก OOP: Encapsulation คุมพิกัด, Inheritance แยกประเภทผู้ใช้, Polymorphism สลับสูตรความเสี่ยง และ Abstraction ซ่อน SQL ครับ"
