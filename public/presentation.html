แบบแผนการออกแบบที่ใช้งานจริง (Design Patterns in Action)

การประยุกต์ใช้ GoF Patterns เพื่อให้โค้ดมีความยืดหยุ่น ดูแลง่าย และทดสอบได้ 100%

Strategy Pattern

CompositeRiskStrategy: สลับสูตรคำนวณความเสี่ยงได้อิสระ โดยรวมค่าน้ำหนักจาก 3 ปัจจัย:

  • ปริมาณน้ำท่วมขัง (Water Level)
  • ปริมาณฝนตกสะสม (Rainfall Forecast)
  • ความถี่ในการรายงาน (Report Density)
Adapter Pattern

External Service Adapters: แปลงโครงสร้างข้อมูลจากภายนอกเข้าสู่ Domain Interface มาตรฐาน:

  • GistdaDisasterService (GISTDA API)
  • OpenWeatherService (Weather API)
  • ป้องกันการผูกติด (Loose Coupling)
Repository Pattern

Data Persistence Abstraction: แยก Logic ฐานข้อมูลออกจาก Business Logic:

  • SupabaseFloodPointRepository
  • JsonFileFloodPointRepository (Mock/Offline)
  • สลับ DB ได้ง่ายเพียงเปลี่ยน Dependency

การผสานข้อมูลดาวเทียมจาก GISTDA Open API

เชื่อมต่อข้อมูลน้ำท่วมและภาพถ่ายดาวเทียมครอบคลุม 77 จังหวัดทั่วประเทศไทย

GISTDA Pipeline & Caching
  • Data Ingestion: เชื่อมต่อ Endpoint https://disaster.gistda.or.th/services/open-api ดึงภาพถ่ายดาวเทียมพื้นที่น้ำท่วมขังรายวัน
  • Multi-Province Aggregation: ประมวลผลและแยกข้อมูลรายจังหวัดทั้ง 77 จังหวัด เพื่อส่งต่อให้แดชบอร์ดและแผนที่
  • In-Memory & File Cache: มีระบบแคชในตัว (TTL 15 นาที) เพื่อลดภาระการเรียก API ภายนอก และตอบสนอง Front-End ภายในเวลา < 30ms
การแปลงข้อมูลสู่ GeoJSON มาตรฐาน

ฝั่ง Back-End จะแปลงข้อมูลดิบจากดาวเทียมให้อยู่ในรูปแบบ FeatureCollection (GeoJSON) เพื่อให้ Leaflet บนหน้าเว็บสามารถเรนเดอร์ขอบเขตน้ำท่วมได้ทันทีโดยไม่ต้องประมวลผลซ้ำ

เครื่องมือรวมกลุ่มเชิงพื้นที่และวาดอาณาเขต (Spatial Clustering)

การคำนวณขอบเขตพื้นที่น้ำท่วมอัตโนมัติ (Dynamic Polygon Zones) ด้วยอัลกอริทึม Convex Hull

1. จุดรายงานเดี่ยว

เมื่อประชาชนส่งรายงานน้ำท่วมเข้ามา 1 จุด ระบบจะบันทึกเป็นหมุดระบุตำแหน่งพร้อมรัศมีผลกระทบเบื้องต้น (Point + Radius Buffer)

2. การเกิด Cluster ซ้ำซ้อน

หากมีการรายงานซ้ำในบริเวณใกล้เคียงกัน (< 500 เมตร) เกินกว่า 2 รายการ หรือมีระดับความรุนแรงระดับวิกฤต ระบบจะจัดเป็นกลุ่ม Cluster ทันที

3. สร้างขอบเขต Polygon

อัลกอริทึม Convex Hull จะคำนวณจุดยอดรอบนอกสุด แล้วส่งออกเป็น Polygon Boundary เพื่อให้แผนที่วาดเป็นอาณาเขตสีแดงโปร่งแสงเตือนภัย

จุดเด่น: ช่วยให้หน่วยงานกู้ภัยและประชาชนเห็นขอบเขตพื้นที่น้ำท่วมจริงแบบเรียลไทม์ โดยไม่ต้องรอประกาศทางการ

สถาปัตยกรรม REST API Endpoints

ช่องทางการเชื่อมต่อข้อมูลความเร็วสูงระหว่าง Back-End และ Front-End

Method Endpoint คำอธิบายหน้าที่
GET /api/points ดึงรายการจุดน้ำท่วมและระดับความเสี่ยง
POST /api/reports ส่งรายงานเหตุน้ำท่วมด่วนจากประชาชน
GET /api/zones ดึงอาณาเขต Polygon พื้นที่ท่วม (GeoJSON)
GET /api/gistda ดึงชั้นข้อมูลน้ำท่วมดาวเทียม 77 จังหวัด
GET /api/stats สถิติสรุปภาพรวมสำหรับหน้าแดชบอร์ด
มาตรฐานการตอบกลับ JSON
  • Consistent Schema: มี success, data, meta, และ timestamp
  • Strict Validation: ตรวจสอบพิกัดละติจูด/ลองจิจูด และเบอร์โทรก่อนบันทึก
  • Interactive API Console: มีหน้าทดสอบ Endpoint ในตัวที่ /api

ปรัชญาการออกแบบ: White Modern UI (No Border, No Shadow)

ฉีกกรอบดีไซน์แบบ AI Slop ด้วยระบบมิติความลึกผ่านความต่างของสีพื้นผิว (Surface Layering)

1. No Border

ห้ามมีเส้นขอบกรอบตัดสายตา ใช้ความสะอาดของพื้นที่สร้างมิติ

2. No Shadow

ห้ามมีเงาดำเบลอๆ ซ้อนกัน ตัดความเทอะทะให้เบาสบายตา

3. Surface Layering

Slate 100 ➔ Pure White ➔ Slate 50 ➔ Slate 200

4. Radius Hierarchy

องค์ประกอบนอกมนกว่าใน (20px > 14px > 10px > 8px)

กฎภาษา: Thai-First & Human Centric ภาษาไทยเข้าใจง่าย • ไร้ศัพท์เทคนิค • ไร้วงเล็บภาษาอังกฤษ

ระบบรายงานน้ำท่วมด่วน (Quick Report Flow ≤ 3 Taps)

ออกแบบโดยยึดหลัก User-Friendly, Compact และเร็วที่สุดสำหรับผู้ประสบภัยในสถานการณ์ฉุกเฉิน

Tap 1: เลือกระดับน้ำ

ปุ่มกด 4 ระดับแบบ Grid สัมผัสง่าย:

  • เล็กน้อย (น้ำขังรอการระบาย)
  • ปานกลาง (ท่วมครึ่งล้อรถ)
  • รถเล็กผ่านไม่ได้
  • วิกฤตจมมิด
Tap 2: เบอร์โทร & ภาพ

ลดขั้นตอนการพิมพ์ด้วย Auto-fill:

  • เบอร์โทรจดจำลง LocalStorage
  • แนบรูปถ่ายสถานที่จริง (Optional)
  • ดึง GPS พิกัดอัตโนมัติ
Tap 3: กดยืนยันส่งข้อมูล

ส่งตรงเข้าสู่ Back-End ทันที:

  • POST /api/reports
  • ประเมินความเสี่ยงอัตโนมัติ
  • จุดรายงานโผล่บนแผนที่สดทันที
