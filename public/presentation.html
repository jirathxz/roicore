สถาปัตยกรรม Clean Architecture & โดเมนโมเดล OOP

แยกแกนกลางทางธุรกิจ (Domain Layer) เป็นอิสระจากฐานข้อมูล และยึดหลัก 4 เสาหลัก OOP

Domain Entities & Value Objects
  • FloodPoint (Entity): จัดการสถานะจุดน้ำท่วม, พิกัด, ระดับน้ำ (เมตร), และจำนวนรายงาน
  • FloodReport (Entity): รายงานจากประชาชน, ระดับความรุนแรง, รูปถ่าย, และเบอร์โทร
  • GeoLocation (ValueObject): ควบคุมความถูกต้องของพิกัด ละติจูด/ลองจิจูด
  • Enums: RiskLevel (วิกฤต/สูง/ปานกลาง/เฝ้าระวัง) และ ReportStatus
1. Encapsulation GeoLocation และ FloodPoint ซ่อนตัวแปรเป็น private ป้องกันค่าพิกัดผิดพลาด
2. Inheritance FloodVictim และ Traveler สืบทอดจาก User เพื่อแยกสิทธิ์การทำงาน
3. Polymorphism IRiskStrategy เรียกเมธอด calculate() เหมือนกัน แต่สลับสูตรประเมินได้อิสระ
4. Abstraction IFloodRepository ซ่อนคำสั่ง SQL และเชื่อมต่อ PostGIS ไว้เบื้องหลัง Domain

3 Design Patterns หลักในการประมวลผลข้อมูล

การประยุกต์ใช้ GoF Patterns เพื่อความยืดหยุ่น การทดสอบ และการประเมินความเสี่ยงอัตโนมัติ

Strategy Pattern
CompositeRiskStrategy

คำนวณคะแนนความเสี่ยงภัยพิบัติแบบไดนามิก โดยรวมค่าน้ำหนักจาก 3 ปัจจัย:

  • ระดับน้ำท่วมขัง (Water Level)
  • พยากรณ์ฝนสะสม (Rainfall)
  • ความหนาแน่นรายงาน (Density)
Repository Pattern
Supabase / PostGIS Repo

แยก Data Access Layer ออกจาก Business Logic:

  • IFloodPointRepository
  • IFloodReportRepository
  • สลับไปใช้ Mock ในการทดสอบได้ทันที
Adapter Pattern
External Service Adapters

แปลงโครงสร้างข้อมูลจากภายนอกเข้าสู่ระบบ:

  • GistdaDisasterService (ดาวเทียม)
  • OpenWeatherService (สภาพอากาศ)
  • ป้องกันการผูกติด (Loose Coupling)

ระบบคำนวณเชิงพื้นที่และ REST API Engine

การคำนวณอาณาเขตน้ำท่วมอัตโนมัติ (Convex Hull) และการเชื่อมต่อข้อมูลความเร็วสูง

Dynamic Flood Polygon Engine
  • Spatial Clustering: ตรวจจับการรายงานซ้ำซ้อนในรัศมีใกล้เคียง (< 500 ม.) เกิน 2 รายการ หรือระดับวิกฤต
  • Convex Hull Algorithm: คำนวณจุดยอดรูปหลายเหลี่ยม ส่งออกเป็น GeoJSON Polygon ให้ Front-End วาดขอบเขตเตือนภัย
  • GISTDA 77 Provinces Cache: ระบบแคชข้อมูลดาวเทียมในตัว (TTL 15 นาที) ตอบสนองได้ในเวลา < 30ms
REST API Endpoints Specification
GET /api/points ดึงรายการจุดน้ำท่วมและระดับความเสี่ยง
POST /api/reports ส่งรายงานเหตุน้ำท่วมด่วนจากประชาชน
GET /api/zones ดึงอาณาเขต Polygon พื้นที่ท่วม (GeoJSON)
GET /api/gistda ดึงชั้นข้อมูลน้ำท่วมดาวเทียม 77 จังหวัด

ปรัชญาการออกแบบ: White Modern UI Architecture

ตัดสิ่งรบกวนสายตา (Zero Border, Zero Shadow) สร้างมิติด้วยระดับชั้นของสีพื้นผิว (Surface Layering)

1. No Border

ห้ามมีเส้นขอบกรอบตัดสายตา ใช้ความสะอาดของพื้นที่สร้างมิติ

2. No Shadow

ห้ามมีเงาดำเบลอๆ ซ้อนกัน ตัดความเทอะทะให้เบาสบายตา

3. Surface Layering

Slate 100 ➔ Pure White ➔ Slate 50 ➔ Slate 200

4. Radius Scale

องค์ประกอบนอกมนกว่าใน (20px > 14px > 10px > 8px)

กฎการสื่อสาร: Thai-First & Human Centric ภาษาไทยเข้าใจง่าย • ไร้ศัพท์เทคนิคบนหน้าจอ • ไร้วงเล็บภาษาอังกฤษ

Quick Report Modal (≤ 3 Taps Flow)
1. เลือกระดับน้ำ: 4 ปุ่มกดแบบ Grid (เล็กน้อย / ปานกลาง / รถเล็กผ่านไม่ได้ / วิกฤต)

Flood Intelligence Dashboard
  • 4 กล่อง KPI: จังหวัดประสบภัย, จุดวิกฤต, รายงานวันนี้, ดัชนีฝน
